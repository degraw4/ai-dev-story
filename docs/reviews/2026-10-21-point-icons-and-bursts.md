# 逐点图标、自动火爆与连续进度验证

日期：2026-10-21。基于本地提交 057e505。用户要求三方向使用不同图标，每次员工头顶跳动对应属性加一，并确认火爆自动触发且真实增加成果。

## 交付

编程为蓝色代码终端，办公为绿色文档，多模态为紫色图像与音符。Canvas 头顶效果和网页属性栏共用 point-icons.js 的像素定义。事件携带实际提交员工，固定 amount=1；显示队列只逐点揭示已经保存的成绩，不调用经营动作。

新项目自动产生一次四工作单位的火爆窗口，在岗员工每单位额外增加一点主攻属性，最多四点。经验、工作量、训练费用与算力速度边界保持。火爆数值是可调基线，用户确认的是自动触发与真实额外加分。

已有 budget112 公司追加一次 enableBurst；当前在研项目保留，下一项目启用。历史存档仍按 acceptedActions 严格重放，compact112 和 classic168 默认不启用。恢复读档直接展示真实分数，不重播历史图标。

阶段进度使用当天实际可推进量与日内时间比例连续填充，主屏和研发窗口显示百分比；暂停冻结、刷新恢复比例，不改变经营结算。

## 验证

- `npm test`：108 项通过。包括逐点守恒、事件归属、火爆真实加四点、算力不改变成果、离职和 Rebo 重置期间不补发、旧档验证及显示队列暂停去重。首次在沙箱内运行的服务监听测试遭遇 EPERM，允许本地端口后重跑全套通过。
- `npm run check:balance`：七条合法路线完整重放通过，四结局可达。最终现金依次 44、363、75、111、−4、19、33；初始两人主攻编程首款为 73、43、32。
- `node scripts/check-research-feedback.mjs`：独立浏览器中一倍和四倍逐帧核对“显示分数增量等于已发出的图标数量”；手动暂停冻结、刷新不重播、管理窗口同步实际数值、减少动画保留真实加分、旧公司启用一次均通过。桌面与手机截图由真实经营夹具运行后手动暂停取得。
- 连续进度七项测试先失败后通过，覆盖阶段末尾、算力、暂停、终局与无法工作；浏览器实测同一游戏日内连续增长，暂停后不变，刷新及研发窗口保持同值。
- `node scripts/check-prototype.mjs`：四视口通用界面回归通过，覆盖方案发布、通知、选人、剧情、迁移与四结局；该次运行先于连续进度接入，随后用上述专项重新检查受影响显示。
- 限定独立检查覆盖主代理的显示队列与客户端接入，发现一次补算跨过方案阶段时发布等待不结束，以及终局返回办公室时底栏滞后。两处已修复，并加入专项浏览器回归。该检查不作为核心实现作者对自己代码的独立审查。

专项中的经营夹具均用合法动作构建；测试只在独立浏览器中模拟了一次延迟帧，不访问用户试玩存档。通用界面检查的通知清理函数增加融资事件处理，并按实际未读队列判断结束，避免在原生窗口关闭事件尚未处理时提前返回。
