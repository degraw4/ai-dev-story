# 首发排名与融资节奏

日期：2026-10-21，基于 7bf8878。用户试玩中四名普通员工的第一款模型达到综合第三，并同时收到种子及专项融资共 120 万，反馈成功来得太快。

## 当前行为

新公司使用 startup112。提高五家竞品的开局和第二代成绩，第三代及最终代保持原分数、原发布日期。种子融资需要至少两款已发布模型且任一款综合分达到 180；专项融资需要至少三款并取得任一专项第一；综合融资需要至少四款并取得综合第一。金额仍为 40、80、160 万，发布数量本身不能直接触发融资。

公司积累继承为 11%，用来保留融资延迟后的中后期追赶能力。初始现金、员工、算力、工期、工资、训练、发布和媒体费用均保持。旧公司固定使用原 campaignProfile，已有现金、榜单及历史成果不重算；体验新开局需明确创建新公司。

## 验证

最终 `npm test` 113 项通过；四种视口的通用浏览器检查通过。

首发、融资数量与新公司标识的三项行为测试先在原实现失败，再由实现通过。测试使用合法招聘与发布动作，遍历两至四名普通员工、三个主攻方向和所有在岗负责人；首发均为第五或第六，未取得专项第一或融资。

`npm run check:balance` 使用当前 startupExamples，四条完整路线的最终现金分别为 49、351、75、−4，四结局可达。标准扩张路线在第 22、32、46 日取得三次融资，112 日共发布 15 款并夺冠。两人保守路线第 48 日取得种子融资，存活到结局。资本路线在总榜融资后实际支付赔偿、辞退全部员工，靠历史产品收入达成；这只是可达性证据，不作为推荐游玩流程。

budgetExamples 的七条历史预算路线继续作为兼容回归，不能当作新公司的策略结论。员工成长的固定对照明确使用 budget112，以保持两条合法历史的公司积累相同、仅比较员工经验。

限定独立检查覆盖根代理写入的 content.js、rules.js、app.js。对照改动前的三种旧公司配置及完整经营重放，未发现历史差异；确认新公司只调整前两代竞品，融资同时检查款数和实际成绩，资金页按公司规则显示。该检查不把核算脚本作者对其脚本的检查当作独立审查。
