# 《AI发展国》产品设计确认与实施摘要

状态：当前重点是 112 日经营节奏、持续竞品压力与主动发布反馈，办公室、员工成长和离职告别已接入。下一次用户评审检查实际操作体验；核算和自动检查不代表真人完整试玩或线上发布。

## 1. 当前产品选择

| 项目 | 已确认结果 |
| --- | --- |
| 经营时间 | 自动推进，可以随时暂停 |
| 团队成长 | 从 2 人逐步扩大到约 6—8 人 |
| 员工替换 | 可以主动辞退后招聘，辞退必须赔偿，员工会撂狠话 |
| 模型开发 | 每款模型独立立项、研发和发布，公司积累保留 |
| 项目并行 | 同一时间只研发一款模型，多名员工可以共同参与 |
| 能力范围 | 编程、办公、多模态，共用流程 |
| 章节推进 | 按游戏时间进入阶段，竞品和新闻推动故事，经营结果改变对白 |
| 结局 | 保留榜单常青树、融资永动机、明年一定第一、发布会照常 |

核心仍是不断发布模型、提高榜分和扩大公司。现金与算力限制投入，客户评价最不重要，实际使用效果不决定胜负。公司设在美国，普通员工按履历、合同和个人特质区分，国籍与肤色不决定属性。

主界面以办公室为中心，整页不滚动，管理操作由边上的按钮进入可内部滚动的二级窗口。公司秘书小满在开张时介绍目标，并根据实际项目进度说明下一步；引导可跳过，也可随时求助。人才市场随首次发布与游戏日逐步开放，完整候选不会在开局全部可招。

## 2. 一局怎样展开

一局是同一家公司从创建到触发一个结局的完整过程，可以存档后继续。正常完整体验目标约 1—2 小时，提前破产可能更短；不要求一次看到所有结局。章节之间不重置公司，发布只是过程中反复发生的经营动作。

**开张与首次上榜 → 融资和扩张选择 → 发布与账单越来越多 → 巨头竞争及成本冲击 → 最终冲榜 → 结局。**

当前用五章组织内容，章节标签可以隐藏，靠新闻、办公室对白和阶段战报自然衔接。没有融资、没有扩张或没有第一名都不会锁住章节；故事根据实际记录变换表达。

| 阶段 | 主要经历 |
| --- | --- |
| 先有一个分数 | 小办公室先给领先留个空格；Meeta 先做大标题、AntiThropic 先查用户，双雄前后脚抢发，把玩家带入第一场榜分竞争 |
| 第一名能换多少钱 | Jeff 离职、显卡促销、巨头融资与 Cloud Code 发布交错出现；玩家开始分清发布稿里的钱和账上能花的钱 |
| 发布稿越来越厚 | DeepPeek R1 在中前期带来成本突破，同行改预算、Nvidya 股价下跌；CodeY、人才竞争与用户核验穿插，热闹新闻最后落回玩家账单 |
| 第一名有保质期 | Meeta 关权重却开招聘，CodeY 重置额度；双雄忙着预热，DeepPeek 正常更新 R2，办公室继续比较发布成绩和实际开支 |
| 最后一次改变世界 | 双雄再次抢发并前后脚准备上市；用户入口层层验证，投资者入口热情开放，办公室回到最后一次研发与发布选择 |

完整章节、26 个故事片段、具体日点与条件对白见 [STORY.md](../design/STORY.md#3-章节演出与贯穿故事)。五章及具体时间长度是助手的可调实施基线，不是用户限定的章数或必须等待的时长。

## 3. 玩家具体做什么

1. 在办公室查看排名、现金、算力和游戏日，通过管理按钮进入对应窗口；小满提供当前目标与带路入口。
2. 看清训练预算并预留发布费与工资，再给模型命名、选主攻方向与方案负责人；先看负责人设计，交付三项初始属性。
3. 全员自动经历数据处理、预训练、后训练、评测，实际工作使员工三项能力成长；增加算力提高速度。管理窗口暂时暂停，关闭后自动继续；主动暂停保留，暂停时不推进账单。
4. 项目完成时主动弹出筹备发布会，决定是否购买一篇报道，再发布真实成绩；主持由系统安排。
5. 发布获得的融资可即时到账；订阅、报道加成在固定账单日结算。用户反馈主动展示评分、用户数、付费人数与收入变化；付费媒体弹出不同风格的标题和节选。

当前简化规则让已完成项目在发布前继续占据项目位置，发布后再开始下一款；不提供多款待发布队列。历史模型始终保留自己的成绩，公司积累不会直接覆盖旧型号。

| 能力方向 | 普通玩家怎样理解 |
| --- | --- |
| 编程 | 写代码、修复错误、通过测试 |
| 办公 | 文档、表格、演示文稿和资料整理 |
| 多模态 | 图片、音频、视频理解与跨媒体交互 |

这些都是争取榜分的领域，不要求玩家亲自写代码或完成办公任务。每款模型有三项成绩和一个主攻方向；综合榜使用同一款模型的成绩，不拼接不同版本。

经营取舍集中在：本款主攻什么、选更强员工还是省工资、快研发还是省现金、扩张还是留预算、是否用赔偿换人、是否现在花钱换取两期媒体订阅收益，以及是否让 Rebo 花钱改善评价。

Morgan Byte 与 Casey Deck 开局可招；Alex Weng 与 Max Score 在首款模型正式发布后开放；Rebo 与 Tim Detmer 第 21 日开放；卡帕题与 Boris Cherry 第 42 日开放。未开放时显示条件，解锁后仍需招聘费、工资预算与工位。日期为可调基线，具体规则以 ECONOMY 为准。小满作为唯一秘书，不参与招聘和工资结算。

五家竞品各保留四款型号，包含开局一款与经营期间三款；同代小版本合并，例如 TalkGPT 5.1、5.2 合并为 TalkGPT 5。模型的数字和代号只表示名字，不直接决定强弱。AntiThropic 编程最强，CloseAI 的办公能力突出，双方多次前后脚发布。工具 CodeY 与 Cloud Code 各安排一次产品发布，不区分版本；它们不是模型，不直接进入模型榜单。

新闻池共有 25 类内容，其中对应十段精选故事的通知用对话、选词和资料翻看呈现，保留可回看的消息流；片段间隔约 8—14 个游戏日，选择在末章有回扣。四条故事线交错出现：

- AntiThropic：早期限制访问，之后设备、付款资料、行为检测越来越繁琐。
- Gloglo 与 Meeta：Jeff Damn 离职，Meeta 挖人并收紧旗舰权重，形成“模型下载通道关闭，招聘通道全天开放”。

- 双雄资本竞争：模型继续训练，融资材料继续写，最后前后脚准备上市；不增加玩家股票交易。

## 5. 四种结局

| 结局 | 表达的经营结果 | 讽刺落点 |
| --- | --- | --- |
| 榜单常青树 | 最终综合第一，公司没有破产 | 荣誉墙满了，用户仍在找文件下载按钮 |
| 融资永动机 | 没守住第一，但融资与现金储备充裕 | 下一代还没完成，下一轮预算已经有了 |
| 明年一定第一 | 活到经营期结束，未达前两类结果 | 总结写进步，计划写第一 |
| 发布会照常 | 资金耗尽 | 办公室熄灯，预录宣传片仍说“这只是开始” |

结局优先级与精确门槛由 [ECONOMY.md](../design/ECONOMY.md) 统一定义，客户评价不覆盖主结局。最后一天必须明确提示发布截止，未正式发布的成果不能补入榜单。

## 6. 实施基线与验证范围

新公司采用 112 游戏日、每游戏日 20 秒、每七日账单、八人工位上限和五章排期作为可调参数。公司积累继承 10%，员工每 120 经验成长一点、单项最多成长六点，中后期竞品成绩加强。倍速、暂停、阅读和提前失败都会改变真实时长。

[REALTIME_BALANCE.md](../design/REALTIME_BALANCE.md) 提供实际核算结果：四类结局均有从标准开局出发的合法路径，覆盖方案、自动四阶段、算力同等成果与关键边界。高效路径的发布数量见核算记录，重复感、末章压力和员工选择价值仍需原型试玩。

真实客户端、独立发布、主动新闻、媒体、用户反馈与辞退告别、事件音效和本地存档已接入。v5 存档接续 v3 与 v4 公司的原有 168 日进度，源存档原文保留；v1 与 v2 可导出。当前界面和规则调整的验证范围见[当前调整证据](2026-10-20-office-pacing-feedback.md)；真人完整试玩、GitHub 仓库与网页部署仍是后续交付。

## 7. 下一次用户评审：节奏与反馈

评审对象是实际可操作的经营循环：从办公室听小满介绍人物、指标、时间控制和管理入口，再创建模型、选择方向与方案负责人、观察自动开发、推进与暂停时间、完成研发、正式发布、看榜单与收入，再采购或招聘并开始下一款。页面必须在不滚动主屏的情况下找到各入口，窗口可以独立滚动且始终能返回办公室。

| 试玩重点 | 需要观察的实际体验 |
| --- | --- |
| 主屏与管理窗口 | 办公室是否铺满中间画面且细节清楚，扩张是否像搬入新总部；关闭管理页与切回页面能否自然继续 |
| 容易理解 | 小满是否先介绍界面再立项，查看资金后是否进入下一目标，方案点数与研发浮字是否容易理解 |
| 打榜反馈 | 发布会、主动用户反馈和媒体报道是否有成就感；用户数、评分和收入变化及到账时间是否清楚 |
| 经营取舍 | 训练、招聘、算力与扩张的预算是否有取舍，媒体报价和两期收益是否清楚；辞退时专属狠话和赔偿是否清楚 |
| 招聘节奏 | 初期候选是否足够，首发与后续开放是否有成长感，条件是否容易理解 |
| 发布节奏 | 第 35、51、79、101 日附近的新竞品是否带来再研发动力，112 日是否仍显拖长；玩家不设竞品四款上限 |
| 演出与听感 | 三家媒体语气和每次文章是否有区分，主动弹窗是否过密，新闻和笑点是否自然，音乐是否疲劳 |

数值核算、代码和浏览器内部检查由助手负责，不要求用户逐项批准实现细节。完整 1—2 小时、存档和四结局体验在后续完整流程评审中验证。代码与素材许可、GitHub 归属和仓库名称在公开发布前确定，不阻止本地原型开发。
