# 媒体报道正文与夸张程度

日期：2026-10-21，基于 bc0eacb。用户要求媒体事件只展示报道，删除推广人数、账单收益和规则尾注；营销号稿件应逐篇更夸张抽象。

## 实现

三家媒体各有六级标题和正文，文章自己用营销口吻夸赞模型，不插入编辑幕后或揭穿稿件的旁白。机器之薪从技术观察写到统一知识理论；量子味从老板群写到银河绩效；新智猿从产品炸场写到宇宙重启。第七篇起继续扩大到更多平行宇宙，不能回到早期模板。

每家媒体独立计算为本公司刊登的文章数。mediaArticle 接收模型记录，只统计同媒体、玩家公司且发布顺序不晚于本型号的文章。未投放的模型不计数，更换媒体从该媒体自己的历史继续；未来文章不会改变旧稿。通知与发布回看使用同一生成函数，不添加存档字段，不改变经营数值。

正文包含媒体、日期、型号、主攻方向、综合分和实际名次，以及夸张报道。不展示推广人数、账期、收入或不叠加规则。费用和效果保留在发布筹备、发布战报、资金页。

## 验证

三个针对性用例覆盖纯报道、同媒体计数与回看稳定、通知和发布标题一致及输入经济状态不变。前两个在修改前失败，修改后通过；通知数据边界用例作为回归保留。最终 npm test 共 118 项全部通过。

隔离 Chromium 的通用回归通过，覆盖四种视口。额外用合法预算公司动作重放，分别生成三家媒体第一篇与第七篇，通过实际通知窗口检查无经营尾注、后期继续升级、刷新不改文字、公司经济快照保持。新智猿第七篇在360×640视口内正文和按钮可读可用。资金页仍显示推广订阅每期10万。

限定独立复核检查计数边界与两个调用入口，未发现未来文章污染历史稿件或经济变更；不代表文案趣味性已经获用户验收。
