# 像素清晰度与 8-bit 音乐迭代验证

日期：2026-10-19，Asia/Shanghai。基线为 9a6ad10，最终产物通过本记录所在提交定位。用户要求保持画风、提高清晰度并进一步参考开罗，同时减少背景音乐的单调感、强化 8-bit 风格；来源见 DEC-038。

## 画面产物

办公室使用 320 × 224 原创逻辑像素，采用整数填色、逐像素描边和设备像素对齐。保留暖白、绿和金色，去除场景点阵干扰，细化四人的头发、衣领与眼镜，以及窗框、键盘、书架、咖啡角、机柜和植物；辅助文字加大并提高对比。

观察了[开罗官方产品页](https://kairosoft.net/game/appli/gamedev.html)及其[人物画面](https://kairosoft.net/game/shared/image/gm8/ss_02.png)、[办公室与评审画面](https://kairosoft.net/game/shared/image/gm8/ss_04.png)，用于理解角色轮廓与物件分层。参考图片仅临时保存查看，没有加入仓库素材；场景和人物由本项目代码绘制。

## 音乐产物

One More Release 为 128 拍每分钟、32 小节、60 秒的原创循环。五段依次为主题、对比、变奏、减层与回接，分界为 0、15、30、45、52.5、60 秒。主旋律使用不同脉冲宽度，辅以短琶音、三角低音和确定性噪声鼓；16 个小节在旋律休止处加入应答。

发布短乐句保持 2.4 秒并统一音色。score.json 是可编辑输入，合成脚本读取谱面生成两段音频；文件格式仍为 22050 Hz、双声道、16 位 PCM WAV，8-bit 指音色与编排风格。

## 实际验证

主代理在最终音频版本执行：

```bash
/usr/bin/python3 scripts/check-preview-audio.py
node scripts/check-design-preview.mjs
```

音频检查环境为 Python 3 与 NumPy 1.24.2。两个命令退出码均为 0。

| 检查 | 实际结果 |
| --- | --- |
| 源谱面与成品 | 两个 WAV 均与重新渲染的音符和参数逐采样一致 |
| 主曲与短乐句时长 | 60.0 秒、2.4 秒 |
| 峰值 | 两个文件均为 0.779968，没有削波 |
| 主曲整体均方根振幅 | 0.115598 |
| 主曲末尾到开头的样本跳变 | 0 |
| 主曲头尾各 100 毫秒的均方根振幅 | 0.145543、0.120648 |
| 最长极低电平片段 | 主曲约 0.132 秒，没有尾部静音填充 |
| 编排变化 | 五段能量、主副旋律应答、脉冲宽度、节奏与低音模式检查通过 |

浏览器检查了员工切换、面板、招聘、发布、战报、四种结局构图和反馈按钮；检查了默认静音、真实播放、跨过音频结尾的循环、音量保存、发布短乐句时降低背景音乐、后台暂停和静音。六张截图在最终画面与音乐版本上生成。

画布原始像素的透明度只有 0 与 255，没有路径抗锯齿产生的半透明边缘；源像素按下列物理像素倍率展示，画布原点也对齐。各组没有横向溢出或场景裁切：

| 网页视口 | 设备像素比 | 每个源像素占据的物理像素边长 |
| --- | --- | --- |
| 1440 × 1100 | 1 | 2 |
| 1440 × 1100 | 1.25 | 2 |
| 390 × 844 | 2 | 2 |
| 360 × 800 | 3 | 3 |

另检查了 390 × 844、设备像素比为 1 的手机主界面。修正了 360 像素宽手机因额外留白导致画布过度缩小的问题。JavaScript 语法与差异格式检查通过。

主代理查看了桌面与手机主图。独立只读代理 clarity_visual_review 比较旧桌面、新桌面、手机与发布战报，并查看参考图，确认原审美保留、角色家具更易区分、主要信息可读，未发现阻塞视觉问题。该复核仅基于截图，没有替代真实触控或用户审美判断。

## 边界与阶段

图像与音频仍服务于固定设计样张，尚无正式经营客户端。经营规则、剧本、数值计算器未修改，本次没有重跑其测试，也没有推送或部署。

音频结构和波形指标不证明旋律悦耳或长期循环不疲劳。未声称进行过真人音乐试听或真实手机触控验证。用户的反馈已落实为可看、可听的产物，表达阶段继续根据实际反馈收尾；本地 Git 保存本次版本。
