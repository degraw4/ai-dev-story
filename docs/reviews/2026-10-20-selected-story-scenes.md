# 十段精选交互剧情验证

日期：2026-10-20。对象：基于本地提交 `fbe57bc` 的本轮修改，最终版本由包含本文件的提交定位。用户授权自行挑选数量、保持定期触发并尝试不同交互。

## 实现范围

十段在新公司第 5、16、29、40、52、63、74、85、93、107 日出现。三段短对话、三段资料翻看、四段选择回应，均最多三步，可随时跳过；完整排期在 [STORY.md](../design/STORY.md)。

每段承接对应原新闻，原始文章仍可在档案查看；第 52 日的 TalkGPT 提示升级为片段，第 51 日 Cloud 发布保留。预热段落在第 74 日呈现后，第 88 日原短文不再次主动弹出。原十五次竞品更新、经济数值和四结局继续由现有规则执行。

标题选择“又”会保存，并在第 107 日得到“小满：日期后面可不能加‘又一天’”的回扣。其他选项改变当段回应或资料顺序。管理按钮只打开对应窗口，实际采购、招聘、发布由玩家执行。玩家资料明确使用当前状态；回看标注当前经营日，行业型号按片段当日筛选，避免把后续 Astra 或 Fable 放进早期片段。

## 行为验证

新增测试先复现缺少故事队列、原新闻未被替代和旧存档当天补弹问题，实施与修复后通过。最终 `npm test` 共 87 项通过，包含：

- 十段排期、唯一标识及三种兼容公司日历。
- 对应原新闻去重、双雄相邻发布保留、原始新闻档案可读。
- 场景生成不修改公司；回看不提前引用未来版本。
- 未发布、没有项目、完成待发布、预计赶不上截止日的真实分支。
- 标题选择存档恢复与末章回扣，经济状态不变。
- 已读当日旧新闻不在升级后重新弹出故事。

`scripts/check-prototype.mjs` 在专用隔离 Chromium 最终输出 PASS，逐一打开十段并实际点击对话、选词和翻页。标题选词后刷新恢复回应，关闭前保持未读；关闭后可从档案回看。每段操作前后比较经济状态，确认现金、模型、员工等事实不变。末段打开研发页时不自动立项。四种视口、手机按钮、已有经营流程、特殊能力、存档保护和四结局检查继续通过。

浏览器测试采用隔离加速时钟，不触碰用户的浏览器进度；截图写入临时目录，只保存本轮剧情证据。自动验证不替代真人对笑点、停顿节奏或阅读疲劳的判断。

## 限定独立复核

另一代理起草内容模块；主代理检查后整合并调整对白，独立运行最终用例。该代理另外只读检查其未实现的 app 与 notifications 集成，并使用独立 Chromium 验证。

检查发现：已有公司恰好停在剧情当天且对应新闻已经读过时，按当前日期初始化会再次弹出同内容剧情。增加先失败用例后，改为已有公司从下一日接入，新公司仍从开局接入。独立复核第 29 日已读标题旧档保存 story-start:30 且不补弹。

同时复核连续未读片段的关闭顺序、选择即时保存但未提前已读、刷新恢复、回看和跳过不改变经济、剧情进入资金页时保持暂停，以及退出管理页后恢复此前运行状态。该限定集成范围没有遗留 P1 或 P2；不扩大为整个游戏的独立代码审查。

## 交付与后续

外层存档保持 v5，阅读与选择使用 observedStoryEvents。现有公司刷新后接续将来的片段；要体验十段完整顺序可以新开公司。其余十六段作为可选素材，后续按试玩选择，不作为本轮缺失项。

当前为本地代码、文档、截图和 Git 归档，没有远端推送或公开网页部署。仍需真人评估剧情是否好笑、单段长度和整局打断频率，以及完整时长；T-01 继续。
