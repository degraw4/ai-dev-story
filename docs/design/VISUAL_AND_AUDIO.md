## 2. 画面语言

原创像素办公室使用等距视角、清楚的人物轮廓、工位、机柜和生活道具，周围保留街区环境。角色与道具分层参考[开罗官方截图](https://kairosoft.net/game/appli/gamedev.html)，场景采用原创 PNG 背景和角色图集，由代码合成实际员工与工作效果。创业办公室和城市总部是两张不同的场景；扩张成功后搬入新总部并使用八个工位，员工和项目继续保留。老板代表玩家，小满是唯一秘书，两人各有固定位置。

界面用暖白纸面、绿色背景、深色描边和少量金黄色突出当前选择。发布会采用深绿色舞台与金色强调，制造“办公室很小，愿景很大”的反差。客户反馈保持可见，但信息权重低于排名与现金。

画面保持暖白、绿与金色的审美，使用清晰轮廓和适量生活道具表现热闹办公室。具体执行原则为：

- 保持等距构图、清晰的像素边缘与场景层次，让人物、工位和设备容易辨认。
- 优先加强人物服装、植物、屏幕、按钮和奖杯的色彩；大面积背景与文字面板保持柔和，避免所有区域同时争夺注意力。
- 用少量明亮的绿色、金黄色和暖色突出工作与发布氛围；现金、榜单和主要操作保持明确的视觉优先级。

下表记录游戏的主要色值。暖白面板与背景保持柔和，主要操作和人物辅助色更鲜明。

| 用途 | 色值 |
| --- | --- |
| 主要文字与描边 | #293b3b、#354b48 |
| 面板纸色 | #fffdf2 |
| 页面背景 | #e8ecdc |
| 主要操作 | #ffd15b |
| 研发与增长 | #aeddb1 |
| 研究员与辅助强调 | #aaa2dd |

创业背景、总部背景和角色图集均为 1536 × 1024 像素。办公室画布铺满可用视窗，以覆盖方式缩放场景，必要时裁切外围街区，工作区域保持居中。画布实际像素尺寸随容器和设备像素比调整，关闭平滑采样以保留像素边缘。角色图集提供员工、空工位、老板与小满，绘制顺序处理桌面遮挡；员工占位读取实际在岗名单，设备灯对应已购算力。老板和小满的网页文字标签随场景坐标定位，正文与数值使用原生网页文字。

界面文字使用系统字体，包含 PingFang SC 与 Microsoft YaHei，不分发字体文件。关键数字、行动和按钮为网页文本，办公室画布承担场景与动画表现。

主屏研发条与模型研发窗口按游戏日内的实际时间比例连续填充，用百分比标明当前阶段。暂停冻结当前位置，变速改变填充速度；达到阶段日结算边界后切换下一阶段。显示进度不额外结算工作量。

AI Dev Story 标志使用厚描边、浅色外轮廓、分层阴影和像素转角，配以原创芯片与上升榜单元素。AI 使用青蓝色，DEV 使用橙黄色，STORY 使用绿色；AI 与 DEV 之间保留明显间距，缩小时仍能识别为两个词。当前文件为 ai-dev-story-logo-v2.png，生成提示与参考来源见[标志说明](../../assets/branding/README.md)。

## 3. 信息和操作

办公室是桌面主屏的主要元素，主页面限制在当前视口内，无需上下滚动。顶部显示现金、算力占用、综合名次、活跃用户、客户评价和当前公司的游戏日，并提供暂停与速度控制。办公室旁放秘书小满与七个管理入口：模型研发、团队能力、人才市场、排行榜、资金扩张、行业快讯、用户反馈。

点击管理入口打开独立窗口，内容可在窗口内部滚动，标题与返回办公室按钮固定可见。打开窗口临时暂停，全部关闭后恢复中断前的运行状态；玩家主动暂停时保持暂停。后台页面、存档冲突和终局不自动推进。管理窗口提供必要的下一步入口，办公室始终是返回位置。

小满使用原创像素头像与简短对话，首次开张主动介绍目标。对话提供带路按钮和跳过入口，办公室保留“问小满”。五步导览先介绍人物、指标、时间与入口，随后提示跟随真实进度：选择方案负责人、立项、设计、自动四阶段研发和发布；首发后说明账上现金与待到账收入；看过资金后继续引导下一款模型，也允许先扩张。她不要求固定点击顺序，不替玩家完成任务，也不产生独立员工费用。

方案负责人以员工卡片选择，桌面两列、手机单列。每张卡片显示姓名和三项当前能力，主攻属性用绿色底色标注；选中卡使用金色背景、边框和“已选”标记。重置中的员工显示完成日与禁用状态。立项与负责人离职后的重选使用相同控件，支持整张卡片点击和原生键盘方向键选择。

团队页显示每名员工当前的编程、办公、多模态能力、经验进度、工资和实际工作状态。经验由真实方案设计和研发产生，能力提升后更新数值并显示成长反馈；休息不补造成长。人才市场显示当前已开放候选的卡片，后续人才通过首次发布或游戏日条件提示，满足条件后才加入可招聘名单。项目完成后主动打开发布准备，只选择是否购买媒体文章；系统选择可用员工主持，玩家无需再选发布负责人，发布不额外占一个研发日。界面区分已到账现金和待账单结算收入，金额、榜分与当前排名优先于对白。立项前显示训练预算，研发页标明已经预付，发布战报保留训练支出；发布筹备分列发布费与媒体费，说明推广期数、预计收益及不叠加。资金页把基础订阅、媒体订阅和待到账奖励分列。

特殊员工卡片用独立区域展示能力名称和“主动能力”或“自动特性”。Rebo 主动区域使用暖金色背景和操作按钮，说明费用、预计评分、完成日和暂时离开研发；反馈页顶部重复提供同一入口。自动特性只说明触发条件，不显示操作按钮。重置完成弹窗使用员工能力类别与浅绿色结果区。

精选剧情使用独立阅读窗口，办公室在后方保持可见。短对话以绿色气泡显示说话人和页码，选择片段以暖金色显示选词按钮与回应，资料翻看使用蓝色纸张与切页按钮。每段最多三步，始终提供“先忙公司”。金额、报价和截止日直接可见；完成后可进入对应管理页，也可返回办公室。行业快讯中的“办公室片段”提供回看，回看标明当前公司数据所属日期。

手机在单屏中保留办公室、必要状态、秘书入口与紧凑管理按钮，完整表格和长说明进入二级窗口。按键有清楚的焦点样式；管理窗口、发布安排、辞退确认与设置窗口支持关闭和键盘取消，独立发布页面有跳过与返回办公室入口。窗口内部允许阅读长内容，不能为了禁止主屏滚动而裁掉表单或返回按钮。

设备像素比指一个网页像素对应的物理像素数量。画布实际分辨率按这一比例设置，场景缩放以填满办公室视窗为目标，界面文字维持原生清晰度。客户端尺寸、主屏溢出、窗口滚动与浏览器操作检查以[原型调整证据](../reviews/2026-10-19-office-shell-three-directions.md)列出的范围为准；设计展示的检查保留在[清晰度与音乐验证](../reviews/2026-10-19-clarity-chiptune.md)。真实手机触控与长时间阅读仍需试玩。

## 4. 办公室与发布演出

办公室采用轻量工作动作、屏幕闪动和机柜灯。方案阶段只有负责人显示设计效果，自动研发时实际参与员工显示工作状态；主屏开发条展示阶段、进度和三项成绩。编程使用蓝色代码窗口图标，办公使用绿色文档图标，多模态使用紫色图像与音符图标，共用 16 × 16 像素定义；员工卡、成绩标签和头顶反馈使用同一套图形。研发时每跳出一个图标与 +1，主屏对应属性显示增加一点。点数按员工分散播放，全局依次错开，同一员工一次只显示一个。普通点可见约0.95秒、火爆点约0.65秒，倍速不缩短停留时间；自动火爆员工播放火焰并较快连续出点，实际额外主攻属性由经营规则结算，每款最多四点，不额外增加经验。员工成长在工位下方另显示“能力提升”，避开头顶点数。

显示队列只消费真实逐点事件。手动暂停冻结出点和移动；管理窗口、后台、终局与减少动画直接同步真实成绩。点数密集时，先播完当前批次再进行下一日结算，不把新一批挤到旧图标上。研发完成时先播完末批点数，再主动筹备发布，尾批也能手动暂停和继续；刷新直接显示已保存成绩，不重播历史点数。具体机制与证据见[逐点反馈记录](../reviews/2026-10-21-point-icons-and-bursts.md)。

方案、发布与庆祝画面由 src/stage-art.js 在 320 × 144 画布上绘制；方案人物复用办公室角色图集。方案过场展示所选员工、实际设计进度、逐步呈现的能力贡献与最终三项初始属性，可以收起且不会跳过游戏日。发布会包含系统选定的主持人、展示屏和观众。首次融资与首次综合登顶的事件卡由真实融资记录恢复，关闭后才确认已读；发布演出中刷新不会丢失尚未阅读的事件卡，确认后不再次主动弹出。用户提供的四张参考截图只用于构图观察。读取系统减少动态效果的偏好；页面进入后台时不继续绘制动画。 方案背景先绘制完整窗户、白板与地板，再叠加透明员工及桌椅图集。图集未加载时只绘制备用人物和桌子，两种前景不叠画；思考和完成提示最后绘制。

玩家正式发布后切换到独立全屏页面，顺序为型号揭幕、三项成绩、真实战报、返回办公室。舞台使用深绿背景与金色标题，约 0.9 秒展示成绩，约 2.6 秒进入战报。战报列出发布时名次、本次名次变化、发布与媒体支出、本次融资、待到账奖励、已计入成绩的实际火爆贡献及当前现金。演出读取已经结算的模型和账目，不能再次执行发布。

跳过直接进入战报；系统要求减少动态效果时直接展示战报。历史模型可从“我的历代模型与发布会”重看，重看不扣费、不奖励。正常发布先播放短乐句，战报出现时根据真实结果选择融资或名次提示音；跳过和返回会清理当前演出的声音。

竞品发布先按当前公司日历入榜并主动展示行业快讯，点击消息可查看独立成绩页面；提示不会直接强制切换到完整发布舞台。DeepPeek 使用左对齐的模型资料页面，展示技术、价格文字和三项成绩，隐藏舞台装饰，不安排主持、采访或争议回应。

新闻、用户反馈、媒体文章和实际辞退使用独立的通知窗口，按顺序呈现，避免叠出多个弹窗。媒体文章分别采用机器之薪的学术包装、量子味的群聊与职场热闹、新智猿的炸裂口吻，按各自历史报道次数逐篇夸张。媒体弹窗只显示新闻标题和正文，推广人数、账单加成和期限放在发布及资金界面。只有实际购买报道才出现该模型的付费文章。

发布后的用户反馈展示本次真实的活跃用户、付费人数、基础订阅收入和评分变化，并列出下一账期预计收入。活跃用户会随排名变化，不表示累计注册；兼容模型缺少历史反馈快照时只展示当前概况。客户评价仍不参与主要胜负判断。辞退告别显示实际员工、已付赔偿与专属狠话，取消或支付失败不播放离职。

消息关闭后才记录已读；刷新能恢复未读消息，确认后的消息不反复主动出现。通知暂停只为阅读服务，关闭后恢复此前运行状态；主动暂停和读档后的暂停均保留。

## 5. 原创音乐

主题名为 One More Release。采用 128 拍每分钟、四拍一小节、32 小节原创旋律，完整循环长 60 秒。不同脉冲宽度的方波音色承担主旋律和短琶音，三角波负责低音，可重复生成的噪声负责打击乐；主旋律休止处安排副声部应答，鼓点与低音在段落间变化。

| 时间 | 编排 |
| --- | --- |
| 0—15 秒 | 主旋律与副声部应答，建立主题 |
| 15—30 秒 | 较低音区、和声与节奏对比 |
| 30—45 秒 | 主题变奏，增加推动感 |
| 45—52.5 秒 | 减少声部，留出呼吸 |
| 52.5—60 秒 | 短过门接回开头 |

发布短乐句长 2.4 秒，采用同一套原创脉冲、琶音、低音与节奏表现。没有外部采样或复刻参考游戏旋律。

[score.json](../../assets/audio/score.json) 是可编辑谱面输入，保存旋律、和声、分段、伴奏与音色参数；[synthesize-preview-music.py](../../scripts/synthesize-preview-music.py)读取它生成 WAV。[音频检查脚本](../../scripts/check-preview-audio.py)验证节拍、谱面与成品一致性、音量与循环边界。

输出为 22050 Hz、双声道、16 位 PCM WAV。PCM 指按采样点记录音频振幅的脉冲编码调制格式；8-bit 指本作的音色与编排风格。峰值约为 0.78，音符使用短包络，末尾的过门延续到开头，不用尾部留白或全曲淡出拼接循环。

首次打开页面静音。用户点击开张或启声按钮后才能播放；背景音乐与事件音效分别调节音量并保存偏好，重新打开页面仍需用户手势启声。发布与结局短句播放时降低背景音乐音量，短句停止后恢复。切至后台暂停音乐并清理事件音效，返回时按已启声状态恢复音乐。

当前已验证谱面重生成与 WAV 逐采样一致，文件没有削波或长静音填充；浏览器可以实际播放、跨过结尾循环、静音、调节音量和保存音量偏好。用户已认可当前音乐。长时间循环是否疲劳、配合实际经营是否合适，仍需要原型试玩；波形与结构检查不能代替这些体验结论。

## 6. 事件音效

事件音效使用方波、三角波与可重复生成的噪声，按事件传达不同反馈。可编辑源为 [events.json](../../assets/audio/events.json)，[生成脚本](../../scripts/synthesize-event-sounds.py)输出十四个 event 音频文件；发布事件复用既有短乐句，共十五种事件。

| 事件标识 | 触发与声音表现 |
| --- | --- |
| ui | 界面选择与任务调整，短促轻点击 |
| projectStart | 新项目立项，逐级上升的启动音 |
| researchReady | 实际研发完成，明亮的完成提示 |
| publish | 正式发布，2.4 秒主题短乐句 |
| rankUp、rankDown | 实际名次上升或下降，对应上行与下行短句 |
| funding | 融资实际到账，清亮琶音 |
| hire、dismiss | 招聘成功的欢迎短句与赔偿离职的下行告别 |
| purchase | 工位或设备购买成功，机械点击与收据音 |
| reset | 启动及完成额度重置，先下降再返回的旋律 |
| news | 新行业消息，低音量广播提示 |
| error | 动作被拒绝，短促低音提示 |
| bankrupt、ending | 破产的低音收束与其他结局的明亮结束句 |

同名短音效不叠播，最多两个事件音效并发。发布和结局优先，期间普通音效不排队积压；融资与名次同时变化时，发布战报优先提示融资。静音、后台、跳过与返回不会留下延迟响起的事件音效。检查入口为 [check-event-sounds.py](../../scripts/check-event-sounds.py) 与客户端音频测试。
